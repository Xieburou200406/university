## 一、日志管理可借鉴点（QS知识体系 §6 + 部署体系 + 部署答疑）

### 1.1 日志粒度两级制：E| 可用，U| 禁用
- QS：`E|` 前缀 = 到期（expiry）级明细日志，归因排查时逐合约看得清；`U|` 前缀 = 聚合日志，**明文禁止用于排查**（聚合把细节抹掉了）。
- 借鉴：vol-demo 的日志分两级——**明细级**（每条信号/每张合约/每次特征计算，含 key 可 grep）与**日报级**（聚合计数，只给"今天健康吗"）。排查永远走明细级。

### 1.2 累计快照必须差分，禁止加总窗口刷新值（铁律级）
- QS：PnL 窗口损益 = 窗口末行值 − 窗口首行值；把 3s 刷新一次的 aPnlChg 加总 = 错账。
- 借鉴：vol-demo 铁律 12（快照差分归因）已有同源思想，升级为可测试约束——daily_snapshot 只追加不更新（DB 约束），归因一律 `mv.diff()`，panel 已实现，补测试锁定。

### 1.3 排查十步 → 数学闭合结案
- QS：delta 损耗排查十步，结案标准不是"我猜是 X"，而是**数字闭合**（各已知项之差收敛到 ±1 tick 才结案）。
- 借鉴：vol-demo 写一份排查 runbook（数据缺失→特征 NaN→弃权原因→预算降级→快照对账→闭合结案），任何"为什么没有信号/为什么亏了"的疑问按固定顺序走，最后一步必须是数字对得上。

### 1.4 结构化事件码 + 单行可抽取（CSV 事件码 / 数字段法）
- QS：CSV 事件码 I/R/C/X/T 标记事件类型；数字段法 `grep … | tr … | awk '{print $N}'` 靠"关键字段位置固定"抽取。
- 借鉴：vol-demo 日志格式定为 `HH:MM:SS|code|key|k=v k=v` 单行制，code ∈ {D数据,F特征,S信号,A建议,B预算,P管线,X异常}；保证 awk 取固定列可用。

### 1.5 daily/curr 软链轮转（目录即指针）
- QS：每日 `daily/YYYYMMDD/`，`curr → 当日`；所有进程只读写 `daily/curr/...`；SOD 建/切目录，EOD 定格落盘，旧目录原样保留 = **回滚底牌**。部署首日 `mv curr 20260921; ln -s 20260921 curr` 把种子挂成当日。
- 借鉴：vol-demo 日志/备份同构——`logs/curr → logs/YYYYMMDD/`，EOD 后定格并备份数据库到当日目录；回滚 = 读旧目录，无需改任何路径配置。

### 1.6 跳变留痕 + 保护性降级
- QS：拟合参数跳变超阈（vol>0.01）打 "Curve fitting jumps" 并**留存盘口快照**；平滑保护跳变则切 Manual 模式 + 告警（cPanic=1）。
- 借鉴：IV/现货跳变超阈 → 记日志 + 保留当日原始数据快照；连续跳变 → 信号链降级（弃权），而不是硬给结论。与 §16.4 失败分级正好衔接。

### 1.7 theta 双锚点：SOD/EOD 各算一次再相减
- QS：tte_sod=(full+1)/252、tte_eod=full/252，两个锚点各算一次 TV，theta = TV_eod − TV_sod；且双口径铁律 **TTE 工作日/252、贴现自然日/365**。
- 借鉴：vol-demo 日 theta 已按"日 theta×365"年化（铁律 2），文档补上"双锚点差分才是正确口径"的说明，并与 252/365 双口径一并写进符号表。

### 1.8 盯盘时间线表 + 双开关 + 身份一致性
- QS：次日首跑盯盘时间线表（时刻→发生什么→在哪看）；auto_sod_eod=1 ∧ active=1 双开关才自动执行；验证连通必须以 tailer 身份（权限语境不同结果不同）；override 赢 pmap，**拿盘中运行态当配置源 = 参数漂移**。
- 借鉴：vol-demo 每日运行时间线表（08:30 拉数→09:25 晨检→15:05 EOD→对账）；管线自动触发 = 计划 ∧ 开关双条件；健康检查与调度跑同一 venv；配置只读 env>默认，运行态永不回写配置。

### 1.9 GB 级日志留在远端
- QS：大日志绝不整份 scp，永远在远端 grep/取尾。借义：vol-demo 的日志查询走 API 端点（分页/过滤），不做"下载整个日志文件"功能。

## 二、交易所知识的友好呈现（三所知识点 + quiz JSON + qsquiz_app.js）

### 2.1 知识点文档的编排法
- 7 部分 16 章：交易所是什么（会员制事业单位）→ 收入与生态 → 产品链（指数→ETF→期权）→ **三所规则对照**（交易时段/到期两套规则/行权交收/合约参数）→ 商品交易所 → **与 QS 系统的连接点** → 术语表 → 考点速查。
- 可借鉴三招：**考点框**（规则旁直接标"这是考点，错一次亏钱"）、**术语表**（每条带一句话人设）、**速记+自测**（12 问带答案）。

### 2.2 quiz 题库 JSON 结构（可直接复用的数据契约）
```json
{"id":"sse-gt-0001","q":"上交所ETF期权的交易时段为？",
 "options":["…","…","…","…"],"answer":"9:30-11:30、13:00-15:00","explain":"连续竞价时段与股票一致。"}
```
- 按 module 分组（sse/szse/cffex/comdty/…），id 自带模块前缀与序号；explain 强制存在——**每道题自带"为什么"**，这是错题本能自我教学的前提。

### 2.3 qsquiz 前端交互模式（练习/测试/考试三模式）
- 练习：单题逐答、即时反馈（正确/错误染色 + 解析）、作答后解锁下一题；
- 测试：混抽 N 题、交卷出分、错题列表（你的答案 vs 正确答案 + 解析）；
- 考试：服务器计时 + localStorage 恢复续答 + 到点自动交卷；
- 关键细节：选项顺序每次打乱（"记住答案本身而不是字母"）、成绩分层染色（≥85 good / ≥60 mid / bad）、toast 统一错误出口、`esc()` 全量 HTML 转义。
- vol-demo 削减版：**练习 + 自测两模式**（无考试/无 token/无成绩单），错题本入 SQLite。

### 2.4 与 vol-demo 决策链的挂钩点
- 铁律 4（到期标签≠真实日期，第四个星期三）= 三所规则考点的直接产物 → 升级为**合约日历卡**（到期倒计时 + 交易日历）；
- 510050 属上交所 → 三所对照表高亮上交所行；
- 知识内容与建议内容物理隔离：教育不进决策链，advice-only 边界不被稀释。
