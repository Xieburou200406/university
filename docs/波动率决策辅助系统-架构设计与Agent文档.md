## 2. 总体架构

### 2.1 分层图

```
┌─────────────────────────────────────────────────────────┐
│  L5 展示层  Web 面板（Streamlit）                        │
│  IV时序 │ 波动率曲线 │ 组合敞口 │ 盈亏归因 │ 回测净值    │
├─────────────────────────────────────────────────────────┤
│  L4 决策层                                               │
│  信号生成 → 风控校验(条件链) → 合约推荐 → 归因说明 → 人工放行 │
├─────────────────────────────────────────────────────────┤
│  L3 组合层  模拟持仓账本 / 快照差分归因 / 回测引擎         │
├─────────────────────────────────────────────────────────┤
│  L2 定价层  BS定价 + 希腊字母 / IV反解 / 曲线拟合(SVI)    │
│             档位分类(ATM/ITM/OTM) / 流动性打分            │
├─────────────────────────────────────────────────────────┤
│  L1 数据层  AKShare采集(显式独立步骤) → 清洗 → 校验       │
│             → 本地存储(SQLite + Parquet 快照)             │
└─────────────────────────────────────────────────────────┘
```

### 2.2 数据流（日频调度，收盘后跑一次）

```
[15:30 定时] → fetch_etf_spot()  → 校验(非空/时间戳/量纲)
             → fetch_option_chain() → 清洗(去停牌/零成交/异常IV)
             → 存 raw 快照 (Parquet, 按日期分目录)
             → pricing: 反解IV → 拟合曲线 → 希腊字母 → 存 processed
             → signal: IV分位数 → 信号状态机
             → risk: 条件链校验 → 输出建议卡片
             → attribution: 持仓快照差分 → 归因表
             → 面板刷新（全部离线读取本地库）
```

### 2.3 技术选型

| 组件 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.11+ | AKShare/量化生态 |
| 数据存储 | SQLite（结构化）+ Parquet（日快照） | 单文件、免运维、快照可回放 |
| 定价 | scipy（Brent/Newton 反解 IV）+ 自实现 BS | 公式透明可审计，不引重型库 |
| 曲线拟合 | SVI 原始形 + scipy least_squares；兜底三次多项式 | SVI 参数少、无蝶套约束好写 |
| 调度 | APScheduler / Windows 任务计划 | 日频一次，越简单越好 |
| 前端 | Streamlit + plotly | 散户本地用，零部署成本 |
| 回测 | 自写事件循环（日频够用） | 不需要 backtrader 这类重框架 |

### 2.4 全局设计原则（来自 design-principles.md）

1. **只生成、不执行**：所有"买入/卖出建议"是只读卡片，唯一出口是"复制参数清单"按钮，人工去券商软件下单。
2. **风控默认值不继承**：风控参数（Vega 上限等）必须显式设置才生效，默认拒绝开新仓（fail-closed）。
3. **联网与计算分离**：`fetch_*` 模块是唯一允许出网的代码，分析模块只读本地库；测试必须包含"断网可跑"用例。
4. **口径铁律**：任何累计类指标（持仓市值、累计盈亏）落库为快照，展示时必差分，禁止用当日全量重算冒充。

## 3. L1 数据层

### 3.1 采集清单（接口名以当前 AKShare 版本实测为准）

| 数据 | 候选接口 | 频率 | 用途 |
|---|---|---|---|
| ETF 现货价 | `fund_etf_spot_em` | 日 | BS 的 S、信号参考 |
| 期权合约列表 | `option_sse_codes_sina` / 东财链 | 日 | 合约全集 |
| 期权日线行情 | `option_sse_daily_sina`（沪）/ `option_sze_daily_sina`（深） | 日 | 结算价、成交量、持仓量 |
| 期权实时/收盘截面 | 对应 spot 接口 | 日 | Bid/Ask（算 IV 用中间价） |
| 无风险利率 | 固定 1.5%~2%（或 shibor 接口） | 周 | BS 的 r |
| 分红/除权 | 手工维护表 | 事件 | 合约调整 |

> 落地注意：AKShare 的期权接口字段和覆盖范围随版本变动，M1 里程碑第一件事就是写 `probe_akshare.py` 逐个接口试跑并把可用字段固化成本地 schema。

### 3.2 清洗规则

- 剔除：当日无成交且无买卖报价的合约、结算价 ≤ 0、Bid>Ask 的倒挂记录（倒挂标记不剔除，供流动性模块用）。
- 剩余期限 T =（到期日 - 当日）/365，按自然日算，到期日从合约代码解析。
- 每个合约落一行：`[date, symbol, strike, expiry, cp, bid, ask, mid, settle, volume, oi, underlying_close]`。

### 3.3 校验与容错

- 行情时间戳必须等于当日，否则整批作废重拉（最多重试 3 次）。
- 合约数量环比突变 >30% 触发告警（防止接口改版静默丢数据）。
- 快照 Parquet 按 `data/snapshots/YYYYMMDD/` 落盘，SQLite 只存派生结果——**保证任意一天可离线回放**。

### 3.4 存储表结构（SQLite 核心表）

```sql
option_daily(date, symbol, strike, expiry, cp, bid, ask, mid, settle,
             volume, oi, underlying_close, PRIMARY KEY(date, symbol));
greeks_daily(date, symbol, iv_market, iv_fitted, delta, gamma, vega, theta,
             tier, liquidity_score, PRIMARY KEY(date, symbol));
iv_history(date, symbol, iv, PRIMARY KEY(date, symbol));       -- 分位数用
position(id, open_date, symbol, direction, qty, open_price, status, close_date);
position_snapshot(date, position_id, mkt_price, market_value,
                  cum_pnl, acc_delta, acc_vega, acc_theta, PRIMARY KEY(date, position_id));
risk_params(key, value, updated_at);                            -- 风控上限，人工写
signal_log(date, signal, symbol, reason, status);               -- 建议流水
```

## 4. L2 定价层

### 4.1 BS 定价与希腊字母（解析式，网上通用公式，代码自持）

- 输入：S（ETF收盘）、K、T、r、σ。
- 输出：理论价、Delta、Gamma、Vega、Theta（**统一量纲**：Vega = 每 1% IV 变动的价格变化；Theta = 每日）。
- 量纲铁律（借鉴 check-risk-pnl 的标定教训）：全系统 Vega/Theta 只允许一种量纲，入库前统一换算，杜绝"vega 标定失败"类事故。

### 4.2 隐含波动率反解

- 用市场中间价反解，Brent 法（有保底区间 [1%, 300%]），深度虚值/实值反解失败则标记 `iv=None`，不参与曲线拟合。
- 卖一/买一存在倒挂时改用结算价反解并降权。

### 4.3 波动率曲线拟合（每日每到期月一条）

- 主模型 SVI：`w(k) = a + b{ρ(k-m) + √((k-m)²+σ²)}`，k = ln(K/F)。
- 参数约束：无蝶式套利（b ≤ 4σ/(T(1+|ρ|)²) 等），拟合失败自动降级为三次多项式。
- 输出：每个行权价的 `iv_fitted` 与 `deviation = iv_market − iv_fitted`（借鉴 vol-arbitrage.md 的偏离概念，作为个券层面的第二信号）。

> 注意：期限结构斜率、25Δ Skew 等派生指标（§5.2b 类比引擎特征向量需要）也在此层产出，统一落 `greeks_daily` 旁的 `features_daily` 表。

### 4.4 档位分类与流动性打分

```
档位：|K/F - 1| < 2% → ATM；Call 侧 K>F → OTM_C（Put 侧反向）……三档五级
流动性分 liquidity_score (0-100)：
    60% 按买卖价差率 spread/mid（越小越好，分段映射）
    25% 按成交量分位（同日同到期月内排名）
    15% 按持仓量分位
低于 40 分的合约：禁止出现在"新开仓推荐"里，只允许平仓建议。
```

## 5. L3 信号层

### 5.1 主信号：IV 滚动分位数（均值回归）

```
取 ATM 合约（或平值插值 IV）日频序列，滚动窗口 120 日（可配）：
    pct = rank(今日IV) / 窗口样本数
    pct ≥ 0.80  → IV高估 → 信号"卖波"（卖 Call/Put 构建收权利金组合）
    pct ≤ 0.20  → IV低估 → 信号"买波"（买 Long Straddle 等）
    其余        → 观望
叠加确认（防单点噪声）：连续 2 日处于同一区间才翻转信号状态（状态机：LONG_VOL / SHORT_VOL / NEUTRAL）。
```

### 5.2 辅助信号：个券偏离（从 vol-arbitrage.md 移植）

`|deviation| > 阈值(默认 2 个 IV 点)` 且流动性达标 → 该合约标记为"推荐执行载体"（信号说要卖波，具体卖哪张由偏离 + 流动性决定）。

### 5.2b 备选信号引擎：历史情景类比（Analog Engine，非均值回归）

用户可切换的**并列**信号源。不做"IV 会回归"的假设，改为：在全部历史交易日里检索与"今天"最相似的 K 天，统计相似日之后各候选策略的实际收益，选历史上最赚钱的那个。

**① 特征向量（每日收盘截面，5~7 维封顶，防止维度灾难）**

```
x(t) = [ ATM IV,
         IV 的 120 日分位数,
         期限结构斜率 (近月IV − 次月IV),
         Skew (25Δ Put IV − 25Δ Call IV),
         方差风险溢价 (ATM IV − 20日已实现波动率),
         标的 20 日动量 ]
```

所有维度先做 z-score 标准化再算距离，距离用加权欧氏距离（分位数和 VRP 权重最高）。

**② 检索与统计**

```
对当日 x(t)：
  1. 在 t 之前的历史日中找 K=20 个最近邻（只用当日以前数据，无未来函数）
  2. 对每个相似日 t_i，向后看 T+5 / T+10 / T+20 三个持有期，
     逐个计算候选策略池的净收益（含买卖价差 + 手续费成本模型）
  3. 用相似度权重 w_i = 1/(1+d_i) 加权汇总每个策略的：
        期望收益 μ、胜率 p、收益分布 P10~P90 分位区间
  4. 选择规则：μ 最高 且 p ≥ 55% 且 P10 > −止損线（下尾可承受）
     三条同时满足才出信号；否则输出"无共识，观望"
```

**③ 候选策略池（固定枚举，模拟持仓直接支持）**

买跨式 / 卖跨式（Δ对冲）/ 日历价差 / 熊市看跌价差 / 牛市看涨价差 / 铁鹰 / 单腿买 Call / 单腿卖 Put / 观望。每个策略是参数化模板（行权价档位、张数由风控条件链定）。

**④ 关键防坑（必须实现，否则回测很好实盘就死）**

| 风险 | 对策 |
|---|---|
| 未来函数 | 特征只用 t 日及以前；相似日收益向后算属于"事后统计"，实盘时该统计来自已完成的历史，合法 |
| 样本不足 | 50ETF/300ETF 期权 2015 年起约 2000+ 交易日；K=20 邻居不足 10 个时直接输出观望 |
| regime 漂移 | 相似度距离加时间衰减因子，近 2 年样本权重 ×1.5；2024/2025 极端行情日单独打标可排除 |
| 过拟合 | 策略池固定枚举不调参；滚动样本外验证：每月末用截至当月数据重检索，统计下月信号命中率 |
| 幸存者偏差 | "最赚钱的策略"是统计结论不是保证，置信度 = 胜率与分位区间宽度，必须随建议卡片展示 |

**⑤ 与均值回归信号的关系**

两个引擎做成**可插拔**（同一 `SignalEngine` 接口，`signal_engine = "percentile" | "analog" | "ensemble"`）。ensemble 模式下两引擎同向才出信号（低频但胜率高），任一引擎独立模式供对比回测。风控条件链对两者一视同仁。

### 5.3 信号输出格式（喂给风控）

```json
{
  "date": "2026-09-30", "signal": "SHORT_VOL", "confidence": 0.84,
  "iv_now": 0.216, "iv_pct": 0.87, "window": 120,
  "candidates": [
    {"symbol": "10005XXX", "action": "SELL", "deviation": 2.3, "liquidity": 78}
  ]
}
```

### 5.3a 执行时序：T 日收盘出信号，T+1 开盘后执行

系统是日频收盘截面系统，时序口径如下（回测与实盘必须一致，否则净值失真）：

```
T 日 15:00  期权收盘
T 日 15:30  定时任务拉取收盘截面 → 计算 IV/曲线/信号/风控 → 生成建议卡片
            （卡片上的"参考价"= T 日收盘中间价，仅供阅读）
T+1 日 9:30 开盘，信号卡片置为"待执行"
T+1 日 9:35~10:00  建议执行窗口：
            - 避开 9:30-9:35 开盘噪声（IV 和价差早晨最宽）
            - 执行前用 T+1 最新行情复核一次风控条件链：
              信号仍成立 + 流动性仍达标 → 显示"可执行"
              任一失效 → 卡片标红"信号过期，作废待今晚重算"
T+1 15:00   未执行则自动作废（信号只管一天，次日以新截面重新决策）
```

三条铁律：

1. **信号有效期 = T+1 一个交易日**。隔日使用旧信号属于口径污染，面板必须显示"信号生成于 T 日收盘，基于 T 日数据"。
2. **执行滑点必须计入回测**：回测中信号价用 T 日收盘中间价，成交价用 T+1 开盘价（或 T+1 中间价），两者之差就是隔夜执行成本——均值回归和类比策略的利润本来就薄，这笔账不算，回测全是虚假繁荣。
3. **不做盘中信号**（M1~M4 范围内）：盘中 IV 抖动大、AKShare 免费接口也不支持可靠的盘中截面；若未来要加"尾盘 14:45 二次确认"模式，作为独立里程碑另议。

为什么"今天推荐明天买"反而是对的：信号基于 T 日收盘截面，如果 T 日盘中就执行，等于用了尚未成立的未来数据（未来函数），回测收益会虚高；T+1 执行是唯一让回测口径与实盘口径完全一致的方案。

## 6. L4 风控层（条件链，移植自 delta-hedge.md §4）

建议仓位由条件链**逐级收窄**，任一环节为 0 即输出"不建议开仓 + 原因"：

| # | 条件 | 默认参数 | 收窄逻辑 |
|---|---|---|---|
| 1 | 组合 Vega 上限 | `abs(Σvega) ≤ VegaLimit`（如权利金余额的 30%） | 本单加入后超限 → 削减张数至恰好不超限 |
| 2 | 组合 Delta 上限 | `abs(Σdelta×S×100) ≤ 账户净值 × 5%` | 建议配对或削减 |
| 3 | 单一行权价仓位上限 | 每 strike ≤ 总仓 30% | 超限换次优合约 |
| 4 | 流动性闸门 | liquidity_score ≥ 40 | 直接拒绝 |
| 5 | 深虚/深实只准平仓 | `|delta| < 0.05 或 > 0.95` | 禁止新开 |
| 6 | 资金占用 | 权利金净支出 ≤ 可用资金 50% | 削减张数 |
| 7 | 信号一致性 | 新仓方向必须与信号状态机一致 | 冲突即拒绝 |

输出建议卡片：`[合约、方向、张数、理由链(逐条显示通过了哪些闸门)、加入后组合 Vega/Delta 前后对比]`。

## 7. 归因层（口径移植自 check-risk-pnl.md）

- 每日收盘对每笔持仓落 `position_snapshot`（快照）。
- 展示时**差分**：`ΔPnL = 今日市值 − 昨日市值`。
- 四项拆解（解释"钱从哪来"）：
  - **Delta 项** = Σ Δdelta × 标的涨跌 × 100
  - **Vega 项** = Σ vega × (今日IV − 昨日IV) × 100（IV 变化）
  - **Theta 项** = Σ theta（每日时间价值损耗，卖方为正）
  - **残差项** = ΔPnL − 前三项（Gamma/曲线形变等），残差占比 >30% 时面板黄牌提示"归因解释力不足"。
- 正反验证：拆解四项之和必须 ≈ ΔPnL（误差 <1 个最小变动价位），否则标记当日快照异常。

---

## 8. 回测模块

- 输入：本地 `iv_history` + `option_daily`（积累不足时先用结算价合成序列，明确标注"模拟数据"）。
- 策略回放：与 §5 同一套信号代码（**信号模块禁止出现任何实盘/回测分支**，保证一致性）。
- 成本模型：买卖价差全额 + 单边手续费（万 2 默认）+ **隔夜执行滑点（T 日收盘中间价 vs T+1 开盘价之差，见 §5.3a）**，这是均值回归策略的死穴，必须显式计入。
- 输出：净值曲线、最大回撤、年化、胜率、按归因四项拆分的收益构成。

---

## 9. L5 展示层（Streamlit 单页多 Tab）

1. **IV 监控**：ATM IV 时序 + 历史分位数带（20%/80% 线）；当日波动率曲线（市场IV散点 vs 拟合曲线）。
2. **信号台**：今日信号卡片 + 候选合约表（档位/流动性/偏离）；卡片标注"基于 T 日收盘数据、T+1 日 9:35-10:00 执行窗口内有效，过期自动作废"。
3. **风控台**：当前组合五维敞口仪表盘（Vega/Delta 用量 vs 上限进度条）。
4. **持仓归因**：累计净值 + 每日四项归因瀑布图。
5. **回测**：净值与回撤。

## 10. Agent 开发文档（如何让 AI Agent 把它造出来）

### 10.1 子代理划分与验收标准

| Agent | 职责 | 输入→输出 | 验收标准 |
|---|---|---|---|
| A1 数据代理 | probe 接口、写 fetch/清洗/校验、建库 | AKShare→SQLite/Parquet | 断网跑分析不报错；插入脏数据被拦截；快照可回放任意历史日 |
| A2 定价代理 | BS+希腊字母、IV 反解、SVI 拟合、档位/流动性 | 行情表→greeks 表 | 已知算例误差 <1e-6；Put-Call 平价校验通过；倒挂合约不崩溃 |
| A3 信号代理 | 双引擎：IV 分位数状态机 + 历史情景类比（k-NN 检索、策略池收益统计、可插拔接口）；信号有效期管理（T 日生成、T+1 过期作废，见 §5.3a） | iv_history/greeks→signal_log | 构造 120 日序列能复现手工计算的分位数；状态翻转需连续 2 日确认；构造已知相似行情，类比引擎能命中预期策略且无未来函数（t 日特征不含 t 后数据）；T+1 日旧信号自动置过期 |
| A4 风控代理 | 条件链、参数管理 | 信号+持仓→建议卡片 | 构造超 Vega 限的持仓，输出张数被正确削减；参数未设置时拒绝开仓 |
| A5 归因与回测代理 | 快照差分、四项拆解、回测 | 快照→归因表/净值 | 四项之和≈ΔPnL；成本计入后净值可复现 |
| A6 前端代理 | Streamlit 五 Tab | 全部表→页面 | 每张图能指到具体表字段；建议卡片无"执行"按钮 |

### 10.3 开发里程碑

- **M1（第 1 周）**：A1 完成，接口 probe 报告 + 建库 + 3 天真实数据落盘。
- **M2（第 2 周）**：A2 完成，能看到当日 IV 曲线图与希腊字母表（此时已有最小可用产品）。
- **M3（第 3 周）**：A3+A4 完成，信号→风控→建议卡片全链路跑通。
- **M4（第 4 周）**：A5+A6 完成，归因瀑布图 + 回测 + 面板上线，模拟盘跟踪 2 周再评估。

### 10.4 风险与边界声明

- IV 分位数依赖历史长度，AKShare 期权历史深度有限，前期分位数用日历价差合成 IV 或延长积累期，面板需标注样本量。
- 流动性差的虚值合约 IV 反解不稳定 → 已由 iv=None 机制隔离，禁止把失败值塞 0。
- 本工具是决策辅助，均值回归在 IV 趋势性抬升（如重大事件前）会持续亏损，信号状态机只能缓解不能消除，文档与面板必须向用户明示。
